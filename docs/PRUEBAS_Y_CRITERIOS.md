# Plan de validación del trabajo académico

Este documento describe **verificaciones a efectuar**; no asegura que se hayan realizado pruebas de software, porque no hay una aplicación funcional incluida.

## Verificación documental
- [ ] BPMN abierto correctamente en un editor compatible con BPMN 2.0; visualización legible.
- [ ] Pools y lanes reflejan roles y separación entre participantes internos y externos.
- [ ] Cada compuerta XOR muestra condiciones claras de salida; la excepción reabre el ticket.
- [ ] La vuelta de fallas en QA hacia N2 está representada.
- [ ] La Entrega 2 conserva metas y precedencias del Gantt originales.
- [ ] Las Entregas 1–4 están identificadas por el contenido que efectivamente se presentó.
- [ ] El README declara el uso de ChatGPT y correcciones humanas.
- [ ] PR, Issues, tabla de seguimiento y, cuando exista, el Projects son accesibles.
- [ ] Revisión real de otra persona documentada y resuelta, o respuesta docente autorizando alternativa.

## Criterios futuros de pruebas funcionales
Si se implementara HU-01: testear obligatoriedad de campos, generación de identificadores únicos y sugerencias de ayuda.
Para HU-02: impedir escalamiento sin diagnóstico; persistir trazabilidad de responsable y fecha.
Para HU-03: definir denominadores cero, validar cálculos y filtrar reportes correctamente.

## Riesgos vigentes
Sin revisor externo y sin GitHub Projects aún no se cumplen dos requisitos explícitos del TP4. **La documentación por sí sola no elimina esas faltas.**
